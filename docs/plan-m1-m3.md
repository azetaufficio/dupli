# Dupli — Piano M1-M3

## Context
Greenfield repository. Goal: central control plane for backing up Windows VMs (folders + PostgreSQL) with restic to S3, in .NET. This plan covers **M1 (local agent), M2 (Management API), M3 (Web UI)**. Out of scope: M4 (Launcher/Updater/rollback), M5 (restore from UI), Authenticode signing (M4). `plan.md` remains the reference spec; below are the decisions taken during the grilling that refine or override it.

## Decisions (override plan.md where they conflict)
| Topic | Decision |
|---|---|
| Runtime | .NET 10 LTS |
| restic repo | **1 repo per VM**. Tags `policy=<id>`, `source=<id>`, `type=dir\|pg`, `db=<name>`. Retention with `forget --tag policy=...` |
| Repo password | Generated by the server, **escrowed** encrypted in the DB (ASP.NET Data Protection, key in a mounted file outside the DB volume). Agent caches it with DPAPI LocalMachine. M1: generated by hand + saved in the operator password vault |
| S3 | Wasabi or B2 (decided at deploy time). Code agnostic: endpoint/region/bucket/prefix/key. Dev/CI on RustFS |
| Ransomware | 1 S3 key per VM restricted to its prefix + bucket versioning + lifecycle noncurrent 30 days. Agent key cannot delete versions |
| S3 key provisioning | Created by hand by the operator in the provider console, entered in the UI, escrowed by the server, delivered at enrollment |
| Tenancy | Single-tenant (operators of one organization only), no Customer entity. Free-form S3 prefix per agent |
| Auth UI | Entra ID, **BFF**: Angular served by `Dupli.Server` (wwwroot), OIDC server-side, HttpOnly cookie + antiforgery. Single container |
| Server hosting | Docker on a Linux VM, reverse proxy with TLS (Caddy), PostgreSQL |
| Agent auth | `POST /api/agents/token` (AgentId+Secret) → 15 min JWT. Server stores only the secret hash. Rotation endpoint |
| Enrollment | Single-use token, 24h TTL, created from the UI on a "pending" Agent. Registration returns AgentId, Secret, repo password, S3 key. MachineId bound |
| Agent install | Single-file self-contained exe. `install --server --token` copies itself to `ProgramData\Dupli\versions\<ver>\`, creates the service, writes `current.json` (M4-ready layout). No MSI |
| Service account | LocalSystem. ACL on `ProgramData\Dupli\config` restricted to SYSTEM+Administrators |
| restic binary | Pinned version+URL+sha256. M1: local config (GitHub URL). M2+: server mirror + manifest. VMs only need to reach the server + S3 |
| pg_dump | Auto-detect from the registry (`postgresql-x64-NN` service) + override. Check pg_dump version ≥ server version |
| PG scope | Discovery of all DBs (excluding template*/postgres) + exclusion list + `pg_dumpall --globals-only` |
| Dump | **Streaming**: `restic backup --stdin-from-command --stdin-filename <db>.dump -- pg_dump -Fc ...`. Password via `PGPASSWORD` env of the child process. No tmp |
| Scheduling | Server-side: cron (Cronos) + timezone per policy (default Europe/Rome). Background scheduler creates a Pending job with `scheduledAt`/`expiresAt` (default 12h). Expired → `Missed`. Coalesce: max 1 pending per policy |
| Job payload | Full policy spec (sources, exclusions, retention), never secrets |
| Idempotency | Local SQLite ledger (`config\agent.db`). jobId seen = not re-run. At startup, a `Running` job → reported Failed(Interrupted) |
| Concurrency | 1 job at a time per agent (local queue) |
| Maintenance | Server-scheduled system jobs: `Retention` (forget+prune, weekly), `RepositoryCheck` (`check --read-data-subset=5%`, weekly) |
| Restore proof | M1: `agent restore --snapshot --target` CLI (target `C:\DupliRestore\<id>` default). M2/M3: job **RestoreTest**: sample of files + last dump into tmp, verify hash + `pg_restore --list`, cleanup. Result in dashboard |
| Notifications | `INotificationChannel` + **Email SMTP**. Alerts: agent offline, backup failed/missed, check/restore-test failed, backup too old. Dedup per condition |
| Migrations | **DbUp** (embedded SQL scripts, run at startup). EF Core for query only, no EF migrations |
| Repo/CI | GitHub monorepo + Actions. Linux job (server + Agent.Core, Testcontainers Postgres+RustFS, real restic). Windows job (Agent, DPAPI, service, single-file publish). Artifacts: Docker image + agent exe |

## M1 — Local agent
1. Solution + Contracts + Agent.Core + Agent, CI skeleton.
2. `ProcessRunner`: absolute path, env vars, stdout/stderr capture, JSON parsing of `restic --json`, kill on cancellation.
3. `ResticToolManager`: pinned download, sha256, `tools\restic\<ver>\restic.exe`.
4. `ResticBackupEngine`: init-if-missing, backup dir (tags, excludes), stdin-from-command, snapshots, restore, forget/prune, check, stale `unlock`.
5. `PostgresDumpProvider`: registry detect, version check, discovery of DBs, globals + per-DB streaming.
6. Error classification transient/permanent (restic exit codes: 1 fatal, 3 partial, 10 repo missing, 11 lock, 12 wrong password) + Polly exponential backoff only on transient errors.
7. Local JSON config (secrets via `agent secret set` → DPAPI), CLI `backup`, `restore`, `forget`, `check`.
8. Serilog: rolling file in `logs\`, enrichers AgentId/JobId/PolicyId/RunId.
9. **Exit gate**: on a real Windows VM, backup dir + PG to Wasabi/B2, restore dir + dump, `pg_restore --list` OK, failure tests (wrong PG password, missing dir, S3 unreachable).

## M2 — Management API
1. DbUp schema: Agent, EnrollmentToken, StorageTarget (encrypted secrets), BackupPolicy, BackupSource, Job (type, state, payload jsonb, scheduledAt, expiresAt, leaseUntil), BackupRun, AgentLog, SoftwareRelease (restic manifest), Alert.
2. Endpoints from §4 + `/api/agents/token`, `/api/agents/secret/rotate`, `/api/tools/restic/manifest`, `/api/tools/restic/{ver}` (mirror).
3. Job state machine: Pending → Assigned → Running → Succeeded|Failed|Cancelled|TimedOut|Missed. Assign atomically (`FOR UPDATE SKIP LOCKED`), lease + timeout.
4. Background services: scheduler (Cronos), offline detector, maintenance jobs, alert evaluator + SMTP.
5. Agent: enrollment, token refresh, heartbeat, poll 30s (configurable), cancel via job state, batched log upload (Info+/Warning/Error).
6. Dockerfile + compose (server, postgres, caddy).

## M3 — Web UI
Angular + BFF Entra ID. Pages: dashboard (online/offline/failed/running counters + agent table §27), agent detail (§28 without Update/Restore; actions: Run now, Restart, Cancel, Generate enrollment token), policy editor (folders, PG instance + exclusions, cron+TZ, retention, storage target), backup history, logs, restore-test result, alerts.

## Verification
- CI green on Linux (Agent.Core + Server + Integration with Testcontainers Postgres/RustFS/real restic) and Windows (Agent).
- M1 gate on a real Windows VM with PostgreSQL (see M1.9).
- M2: agent enrolled against a docker-compose server; scheduled job executed; `Missed` with agent offline past the window; SMTP alert received (MailHog in dev); duplicate job not re-executed; agent restart during backup → Failed(Interrupted) + stale unlock.
- M3: end-to-end Entra login, policy creation, Run now, history/log visible, RestoreTest green.
